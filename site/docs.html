Hue Hop Docs

Every letter hops a hue.

Start

Get Started

Three steps: load it, wrap a heading, pick colors. Working with a coding assistant? Skip to Build with AI .

Load It

npm CDN Self-host

In your terminal

npm install hue-hop

In your JavaScript

import 'hue-hop';

Add drift with import 'hue-hop/drift.css'; . That needs a bundler that handles CSS (Vite does). Otherwise load dist/drift.css with a <link> .

A whole page

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="color-scheme" content="light dark">
    <script
      type="module"
      src="https://cdn.jsdelivr.net/npm/{{cdn-version}}/dist/hue-hop.js"
    ></script>
  </head>
  <body>
    <h1><hue-hop hue="dusk">Midnight Marauders</hue-hop></h1>
  </body>
</html>

Already have a page? Copy only the <script> tag.

Add drift with a <link> to dist/drift.css in the same folder.

Keep the version in the URL until 1.0. A breaking change can't reach your site until you choose to update.

Save hue-hop.js to your site's /js/ folder. Add drift by saving drift.css to /css/ and loading it with a <link> .

In your HTML

<script
  type="module"
  src="/js/hue-hop.js"
></script>

Then set color-scheme so the hues follow the visitor's light or dark setting. Without it, dark pages get the light colors.

In your head

<meta name="color-scheme" content="light dark">

Loading it defines <hue-hop> , unless something on the page already did. Types ship in the package. The HueHop class is exported too, for another tag .

Wrap a Heading

Put the element inside the heading, around the words, and pick a look with hue . Each letter gets one flat color, one step on the way from the start color to the end. One hop is one color step.

The heading stays one piece of text, so select, find, and copy work like on any heading. Kerning holds, links inside keep working, and nothing moves when the colors load.

Pick Colors

Use hue for one of the seven ready-made pairs, or start and end for your own. Set only one end and Hue Hop picks the other. See Hues and Your Own Colors .

Tune it with curve , boost and shift on the same tag. For a whole site, set --hop-curve and the rest on :root instead. See Tuning the Ramp .

Where It Fits

Short text that names something: a title, a name, a number. It isn't meant for body copy, which gets hard to read when every letter changes color.

A heading that wraps keeps one ramp across its lines. Links and other inline markup can sit inside, and they keep working. The colors run straight across them (see Styling Around It ).

Use as many as you like on one page. They share their styles (see How It Works ).

Use

Hues

Seven ready-made pairs come with the element. Pick one with hue .

Sample hue Dark scheme Light scheme
Electric Relaxation dusk pale sky to blue-violet steel blue to indigo
Aquemini reef pale aqua to blue teal to navy
Award Tour fern lime to pine green to dark pine
Liquid Swords ember pale amber to red bronze to deep red
Juicy guava peach to magenta terracotta to berry
Passin' Me By orchid blush pink to aubergine rose to deep violet
Paid in Full honey butter yellow to rust ochre to rust

The light-scheme starts are deeper, so they stay readable on light pages. Flip the side switch in the header to see both.

Every letter of the seven hues passes 4.5:1 contrast, with drift off or on at its default range. That's checked on light pages from #f5f5f5 to #fff and dark pages from #000 to #1a1a1a . On other backgrounds, you'll need to check them yourself.

The hues need color-scheme . They use light-dark() , so without a color-scheme on the page you always get the light colors. See Light and Dark .

Display

Add display for large headings. Its colors sit closer to the page color and pass 3:1, the bar for large text. It isn't meant for body-size text. display only works with hue . On its own it does nothing.

Change One End

A start or end attribute wins over the hue's, and so does a --hop-* value set on the element. So you can pick a hue and change one end.

A changed end is your color, so its contrast is yours to check. See Keep Them Readable .

A rule on the element beats the hue, even inside a cascade layer, so Tailwind v4 utilities work with no setup. A color set on a parent, like :root , loses to the hue. A boost set there beats it. See Which Value Wins .

Your Own Colors

Set start and end to any two colors. start colors the first letter and end the last, and every letter between gets one flat step on the way. They set --hop-start and --hop-end on the element.

Any CSS color works, var(--brand) and light-dark() included. A var() that points nowhere counts as left out, so Hue Hop picks its partner. A typo ( start="tael" ) shows plain text. Set neither end and the text keeps its normal color.

One End

Set only one and Hue Hop picks the other. It keeps your lightness and intensity and turns the hue 50 degrees around the color wheel, away from yellow ( Keep Them Readable says why).

As Custom Properties

Set --hop-start and --hop-end anywhere they'll inherit: :root , a class, your design tokens, or one element's style . Use them for colors shared across a site, or colors that follow a theme.

Each new attribute value adds a small style rule to the page. For a color that changes every frame, set --hop-start in style instead.

Which Value Wins

Strongest first. Each one beats everything below it.

The style attribute, unless a stylesheet uses !important .
Beats attribute
An unlayered rule more specific than hue-hop[start] , like .card h2 hue-hop .
The attribute
start , end , curve or any other tuning attribute on the element. Each value becomes a rule like hue-hop[start="teal"] , and that's the rule yours has to beat.
Below that

The hue attribute's own colors. Its boost is the exception: an inherited --hop-boost beats it.

From JavaScript

el.hue , el.start , el.end , el.display and el.drift read and set the attributes. So do el.curve , el.boost , el.shift , el.driftRange and el.driftCycle . The last two set drift-range and drift-cycle . All of these except display and drift take null to remove the attribute. display and drift take true or false . Setting a property works the same as setting the attribute, even before the element has loaded. That covers frameworks that set properties (Angular, Solid, Lit's .start= ).

Change the text any time. The colors follow.

Keep Them Readable

The element can't see the background, so it can't check your colors for you. These rules keep both ends readable. Write your ends in oklch() so you can see the lightness (the first number).

Page Body text (4.5:1) Display (3:1)
Light, #f5f5f5 to #fff both ends at 52% or darker both ends at 62% or darker
Dark, #000 to #1a1a1a both ends at 65% or lighter both ends at 55% or lighter

So for body text on a light page, start="oklch(50% 0.15 250)" passes. The 50% is the number to watch.

These hold for any hue and any chroma a screen can show. Lightness steps evenly from one end to the other, so if both ends pass, most letters between them do too. Ends far apart on the color wheel (green to violet, say) can still dip in the middle, and boost makes that more likely. Check the middle letters.

On any other background, check the contrast yourself. The ready-made hues go a little past these numbers, because each one was measured for its own colors.

Yellows can't stay bright that dark. At 52% , a yellow holds about half the color (OKLCH chroma) a blue or pink can, so it goes dull. For a yellow start, use the display bar or a dark page.

Or let the Studio do it. It checks every letter against your page color, and its Fit button moves the ends until every letter passes, or tells you it can't.

Light and Dark

The element has no theme logic. It reads --hop-* live, so when your theme changes them, the letters follow with no re-render. Flip the side switch in the header. Examples that use a hue or light-dark() follow.

Pick colors per scheme in one of three ways.

Theme tokens Scheme rule light-dark()

Point both ends at tokens that already flip with your theme.

In your CSS

:root {
  --hop-start: var(--brand-500);
  --hop-end: var(--accent-500);
}

Set the ends again in a scheme query, or under the class your theme switch sets (like .dark ).

In your CSS

:root {
  --hop-start: teal;
  --hop-end: royalblue;
}

@media (prefers-color-scheme: dark) {
  :root {
    --hop-start: aquamarine;
    --hop-end: lightskyblue;
  }
}

light-dark() picks its first color on a light page and its second on a dark one. It needs color-scheme on the page ( :root { color-scheme: light dark; } ), or you always get the light value. This page sets it, which is why the example flips.

Drift

drift.css slowly sways the hues back and forth. Load it once (see Load It ), then add drift to the <hue-hop> .

Two attributes set the sway, like <hue-hop hue="ember" drift drift-cycle="4s"> . The range is a plain number, and the cycle is a time like 10s . Each has a custom property too, for setting it in CSS. Neither does anything without drift .

Attribute Custom property Default What it does
drift-range --hop-drift-range 24 How many degrees the hues sway each way.
drift-cycle --hop-drift-cycle 10s How long one full sway there and back takes.

Drift only turns hues, and lightness holds. Contrast can still shift a little as the hues turn, so leave some margin at the start and end colors. Drift stops when the visitor prefers reduced motion, and under forced colors and increased contrast.

A subclass under another tag drifts too, as long as it has text. Inside another component's shadow root, load drift.css on the page and in that root.

Studio

  1. Pick a start and an end color, or let it pick one.
  2. Set the background to your page color. Every letter's contrast is checked against it. Flip the side switch in the header to set your other scheme's page.
  3. If a letter fails, press Fit. It moves the ends until every letter passes, or tells you it can't.
  4. Open Code and copy the markup.

Customize

Tuning the Ramp

Three attributes shape the steps between your two ends: curve , boost and shift . Set them on the heading you're tuning, like <hue-hop hue="reef" curve="2"> . The values are what you'd write in CSS. To tune every heading at once, see Tuning in CSS .

Curve

How the steps are spaced. At 1 , the default, they're even. Higher stays near the start color longer. Lower gets to the end color sooner.

Boost

Extra color intensity (OKLCH chroma) for the middle letters, so the blend doesn't go dull halfway. The two ends don't change. The default is 0 , and every ready-made hue sets 0.021 . A boost attribute beats a hue's, and so does any --hop-boost , even one set on :root .

Too much boost gets clipped. Past the sRGB range (the colors a typical screen can show), the middle letters get cut back, and on a white page that can lower their contrast. Check the middle letters. The Studio checks them after the clip, so it catches this.

Shift

Turns each letter's hue by this many degrees around the color wheel. Write a plain number ( 30 , not 30deg ). The default is 0 . Lightness holds, so it's a quick way to try a pair in another color without picking new ends.

Contrast can still move a little as the hues turn. A shifted ready-made hue isn't the one that was measured, so check it.

Tuning in CSS

Every tuning attribute has a custom property. Set it on :root or a class, and every heading under it follows. No attribute needed.

Attribute Custom property Default
curve --hop-curve 1
boost --hop-boost 0
shift --hop-shift 0
drift-range --hop-drift-range 24
drift-cycle --hop-drift-cycle 10s

In your CSS

:root {
  --hop-curve: 1.4;
  --hop-boost: 0.03;
}

.hero {
  --hop-drift-cycle: 20s;
}

@media (min-width: 60rem) {
  :root {
    --hop-shift: 20;
  }
}

An attribute on a heading beats these, so one heading can still differ. To beat an attribute from CSS, use style or a more specific rule. See Which Value Wins .

Styling Around It

<hue-hop> is an inline element. Font, size, weight, and letter spacing work on it the way they work on a <span> . Style the heading around it as you already do.

Your color
color is the exception. The letter colors paint over it, so yours only shows where the effect is off: an older browser, neither end set, forced colors, or increased contrast. Set it anyway. It's the fallback.
Selected text
A ::selection rule of yours that sets color wins in every browser, and the letter colors come back after. Without one, it depends on the browser (see Browser Differences ).
Gradient text
background-clip: text with a transparent fill hides the effect, because the transparent fill wins. Use one or the other.
Links inside
They lose their own color in every state, hover and visited included. They keep their focus ring and underline. The underline's color depends on the browser (see Browser Differences ).
Hover and animation
A :hover rule that sets --hop-start or --hop-end works, but the colors snap instead of fading. Those properties aren't registered with @property , so a transition on them can't run.
Your highlights
A search-term marker, say, paints above Hue Hop's, because every Hue Hop highlight has priority −1. See Highlights .

Integrate

Frameworks and Editors

It's a plain custom element. Plain HTML, Svelte, and Lit need nothing. TypeScript and React get their types from the package. Vue and Angular each need one setting.

It works inside another component's shadow root too. For drift there, load drift.css in that root as well as on the page.

TypeScript

hue-hop.d.ts ships in the package. It adds <hue-hop> to HTMLElementTagNameMap , so document.querySelector('hue-hop') comes back as a HueHop . It also types the element in React JSX: hue (the seven names), start , end , drift , and display . Nothing to declare. The seven names are exported as HueName .

React

React needs nothing. It sets start and end as attributes or as properties, and the element reads both.

Turn on drift and display with the bare name, like <hue-hop drift> , and leave them out to turn them off. React 19 treats drift="" as off, and React 18 treats drift={false} as on.

Server Rendering

Importing it on the server is safe. There's no browser there, so it does nothing, and the heading goes out as plain text. The colors arrive when the same import runs in the browser.

So import it from code that also runs in the browser. Code that only runs on the server never defines the element on the page.

  • Next.js: import it in a file that starts with 'use client' , not in a Server Component.
  • Astro: import it in a <script> tag, not in the frontmatter.
  • Nuxt: import it in a plugin named like plugins/hue-hop.client.js .
  • SvelteKit: import it in the component. That runs in both.

Vue and Angular

Both need to be told that <hue-hop> isn't one of their own components. In Vue, add this to the Vue plugin in vite.config.js :

In vite.config.js

vue({
  template: { compilerOptions: { isCustomElement: tag => tag === 'hue-hop' } },
})

In Angular, add CUSTOM_ELEMENTS_SCHEMA to the component that uses it:

In your Angular component

@Component({
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
})

Another Tag

The HueHop class is exported. To use another tag, register a subclass:

In your JavaScript

import { HueHop } from 'hue-hop';

customElements.define('my-hop', class extends HueHop {});

HueHop itself won't work here. The import already registered it, and a class can only be registered once. Your tag and <hue-hop> can share a page. To leave <hue-hop> undefined, import from hue-hop/element instead. See Exports .

A subclass that defines its own observedAttributes must include ...super.observedAttributes and call super.attributeChangedCallback() , or start and end stop updating.

The hues and drift follow your tag on their own.

The element attaches a shadow root holding one <slot> , and your text stays where you wrote it. A subclass can attach its own root in its constructor instead. Any later and the browser throws. Keep a <slot> in it, or the text won't show. A closed root goes without the hues, because the element can't reach it.

A subclass can't call attachInternals() . The element already did, and an element only gets one.

Tailwind and Cascade Layers

CSS on the element beats a hue with no setup, layer or not. So do --hop-drift-range and --hop-drift-cycle . The one exception is a layered rule that sets animation on a drifting element. drift.css sits in a layer named hue-hop , so list that first for your rule to win.

In your CSS

@layer hue-hop, theme, base, components, utilities;

Content Security Policy

The element adds its styles from JavaScript as constructed stylesheets (built in script, not written into the page), not a <style> tag. So your policy doesn't need style-src 'unsafe-inline' for it. drift.css is a plain stylesheet file, so load it from a host your policy already allows.

Editors

custom-elements.json describes every attribute, property, and custom property in the Custom Elements Manifest format. The package's customElements field points to it, so any tool that reads the format can find it. Scripts can import it as hue-hop/custom-elements.json .

Testing Your App

Screenshot Tests

Drift keeps moving, so screenshots of it won't match from run to run. Emulate reduced motion and drift holds still. In Playwright:

In your Playwright test

await page.emulateMedia({ reducedMotion: 'reduce' });

Reading a Letter's Color

Each step has its own highlight: hue-hop-0 for the first, hue-hop-1 for the next, and on up. Up to 64 letters, that's one per letter. Read one with getComputedStyle :

In your JavaScript

getComputedStyle(el, '::highlight(hue-hop-0)').color;

The value is fixed for the current scheme. A copy of it won't follow a theme switch. For colors that do, see Coloring Things Nearby . Stay below el.hops : a higher step can return a wrong color.

Test DOMs

jsdom and happy-dom have no highlights, so the element goes inert there. It's defined, it never draws, and it logs nothing. That's what Vitest's jsdom and happy-dom environments do, checked with jsdom 30.1, happy-dom 21.0, and Vitest 5.1.

Wiring up a DOM by hand? Copying only window , document , HTMLElement , and customElements onto the global is enough. With no CSS , the element loads and stays inert.

el.hops is 0 off the page or without support, test DOMs included.

Highlights

The colors are highlights in CSS.highlights , one per step: hue-hop-0 up to hue-hop-63 . Every one has priority −1, so your own highlights (a search-term marker, say) paint above them. The names are public and won't change.

CSS.highlights.clear() removes the colors until the text changes or the element reconnects. To read a letter's color, see Reading a Letter's Color .

Step Count

Every letter except a space gets its own step, up to 64. Longer text shares steps, so a 200-letter heading still runs the whole ramp at about three letters per color. More steps would slow every restyle (the browser working out styles again) on the page, theme switches and drift included.

Type in the box to watch the count.

el.hops returns the count as a read-only number. It's 0 when the element is off the page or the browser lacks support.

Exports

The module exports the HueHop class and defines <hue-hop> with it, unless something on the page already did. To register it under another name, see Another Tag .

hue-hop/element exports HueHop without defining a tag, for a scoped registry or your own prefix. Load it or hue-hop , never both, or the page runs two copies.

Browser Support

The colors need two things from a browser: the CSS Custom Highlight API, and custom properties that work inside a highlight. These versions and anything newer have both:

  • Chrome 134+
  • Firefox 140+
  • Safari 18+
Older browsers show the heading in its normal color. The element checks for CSS.highlights and :state() as it loads, and does nothing unless it finds both. There's no polyfill. Chrome 105 to 133 have the API but can't read custom properties inside a highlight, so they show plain text too, never a wrong color. Safari 17 is unmeasured.

Before It Loads

Without JavaScript, or before the element loads, the heading is plain text in its normal color. When the colors arrive, nothing moves, so there's no layout shift to prevent and nothing to load ahead of it.

Known Limits

Colors

  • The element can't check contrast at the start and end colors, so that part is up to you.
  • Two ends, no middle stops.
  • A typo in a color ( start="tael" ) shows plain text. A var() that points nowhere counts as left out, so Hue Hop picks its partner instead.
  • Ends far apart on the color wheel, and boost, can push the middle letters past what an sRGB screen can show. They get clipped, by an amount that depends on the colors, and on a white page that can lower their contrast. Check the middle letters.
  • User stylesheets and extensions that force a text color still show the colors. A highlight's color paints above the element's color, !important included.

Text

  • Links inside, selected text, gradient text, and ligatures each behave a little differently. See Styling Around It .
  • A <hue-hop> inside another colors its own text. The outer one skips it.
  • Find in page still shows its matches. The colors come back after.
  • Color emoji keep their own colors and use one step each.
  • A letter split across two elements (a base letter in one, a combining mark in the next) counts as two steps.
  • The steps follow reading order, so mixed-direction text jumps around visually.
  • Text passed through your own <slot> inside the element isn't colored.
  • Safari can leave letters plain if they're hidden inside the hop and shown later, or if content-visibility is on the hop itself. Hide the hop with display: none or hide an ancestor. Those recolor when they show.
  • Screen-reader-only text inside the element still uses up steps, so the visible letters may not reach --hop-end .

Setup

  • A subclass with a closed shadow root doesn't get the hues. Its letters still step if you set your own ends.
  • A subclass that defines its own observedAttributes needs two extra lines, or start and end stop updating. See Another Tag .
  • A subclass with no text, like one wrapping only an SVG, doesn't drift.
  • A subclass can't call attachInternals() . The element already did. See Another Tag .

Troubleshooting

Nothing is colored.
  • A curve , boost or shift value isn't valid CSS, like shift="30deg" (write 30 ). Hue Hop passes values through unchecked, so the letters fall back to the heading's normal color. A bad drift-range or drift-cycle only stops the sway.
  • An older browser. Below the floor the heading stays plain on purpose. See Browser Support .
  • A typo in a color ( start="tael" ). Correcting the spelling fixes it.
  • hue isn't one of the seven ( hue="teal" ). An unknown name sets no colors. Use a name from Hues , or set start and end .
  • Both ends point at a var() that doesn't exist. One missing end is fine, because Hue Hop picks a partner. With both missing there's nothing to step. Define the variable.
  • Forced colors or increased contrast is on. The effect turns off on purpose. See Accessibility .
  • You put your own <slot> inside the element. Text passed through it isn't colored. Put the <hue-hop> around the text where it's written, not around the slot.
The dark hues don't show.
No color-scheme on the page, so light-dark() always picks the light value. Add :root { color-scheme: light dark; } . See Light and Dark .
My CSS doesn't override the hue.
You set --hop-start or --hop-end on a parent, like :root . The hue's own colors on the element beat inherited ones. Set yours on the element. See Change One End .
The middle letters look wrong.
Ends far apart on the color wheel, or too much boost, push the middle letters past what an sRGB screen can show, and they get clipped. Lower the boost or bring the ends closer, then check the middle letters. See Boost .
Drift doesn't move.
  • drift.css isn't loaded. Load it (see Load It ).
  • The element is in another component's shadow root. Load drift.css on the page and in that root.
  • Reduced motion is on. Drift holds still on purpose, and under forced colors and increased contrast too.
Colors don't follow my theme switch.
--hop-* set on :root in a prefers-color-scheme query, while your theme switches on a class. Set them under that class too.

Still stuck? Ask in Issues (see Support ).

About

How It Works

Hue Hop never splits your text. A word stays one element in one text node, and the colors are painted over it. Here's one word taken apart. Move the fader to change how its colors are spaced.

Ranges
The CSS Custom Highlight API paints the colors. Each letter gets a StaticRange (a fixed start and end point in the text) over the real text node, and each step is one highlight. So there are no spans. The element adds one thing: a shadow root holding one <slot> . Your text stays where you wrote it.
Colors
Each step's color is worked out in CSS: color-mix() in OKLCH between the two ends. The curve spaces the steps, boost saturates the middle, and shift and drift turn the hue. So a theme switch or a --hop-* change recolors the letters with no JavaScript. Read the formula in the repo.
Stylesheets
The styles arrive as constructed stylesheets. The hues sit in the element's own shadow root, as :host rules, which is why CSS on the element beats them and an inherited value doesn't. The rest goes on the document, or on the shadow root the element sits in. Every heading in a root shares one sheet. It holds one rule per distinct start or end value, so a page of headings with the same ends adds two rules. At 256 rules, that sheet is rebuilt from the elements still on the page.
64 steps
In Chromium and Safari each restyle costs about the square of the step count, so longer text shares steps.

Inspiration

It started with the per-letter wordmark on mdrng.com , and one idea:

Each letter's color should be chosen, not smeared.

Why stepped
One flat color per letter is a choice you can check. Every letter's contrast is a number.
Why now
The CSS Custom Highlight API ships in Chrome, Firefox, and Safari. That's what lets the text stay text.

How It Compares

Support

Bugs, ideas, and questions go in GitHub Issues .

Bug reports
A report helps most with your browser and its version, the markup, the colors, the page background, and a screenshot.
Big changes
Changes to the API, the formula, or the seven hues start as an issue, so you get an answer before you write code. See CONTRIBUTING .

Stats

The site counts visits with Umami , plus which install tab you open, which code you copy, and when you copy a Studio link. There are no cookies, and nothing in the totals identifies you. The package itself counts nothing. To leave yourself out, open ?stats=off once in each browser. ?stats=on puts you back.
