Hue Hop Docs

Every letter hops a hue. Everything about the element is on this page, from the first import to the API.

Start

Get Started

Three steps: load it, wrap a heading, pick colors. Working with a coding assistant? Skip to Build with AI .

Manifest and Types

The package ships two files for your tools. custom-elements.json lists every attribute, property, and custom property, and the package's customElements field points tools at it. hue-hop.d.ts types the element, React JSX included. See Frameworks and Editors .

Use

Hues

Seven ready-made pairs come with the element. Pick one with hue . Each pair has a dark side and a light side. The descriptions below are for the dark side.

Sample hue Goes from (dark side)
Electric Relaxation dusk pale sky to blue-violet
Aquemini reef pale aqua to blue
Award Tour fern lime to pine
Liquid Swords ember pale amber to red
Juicy guava peach to magenta
Passin' Me By orchid blush pink to aubergine
Paid in Full honey butter yellow to rust

On the light side the starts are deeper, so they stay readable on light pages. Flip the side switch in the header to see them.

Every letter of the seven hues passes 4.5:1 contrast, with drift off or on at its default range. That's checked on light pages from #f5f5f5 to #fff and dark pages from #000 to #1a1a1a . On other backgrounds, you'll need to check them yourself. Every hue also sets --hop-lift to 0.021 .

The hues need color-scheme . They use light-dark() , so without a color-scheme on the page you always get the light side. See Light and Dark .

Display

Add display for large headings. Its colors sit closer to the page color and pass 3:1, the bar for large text. It isn't meant for body-size text. display only works with hue . On its own it does nothing.

Change One End

A start or end attribute wins over the hue's, and so does a --hop-* value set on the element. So you can pick a hue and change one end.

A changed end is your color, so its contrast is yours to check. See Keep Them Readable .

A rule on the element beats the hue, even inside a cascade layer, so Tailwind v4 utilities work with no setup. A value on a parent, like :root , loses to the hue. See Which Value Wins .

Your Own Colors

Set start and end to any two colors. start colors the first letter and end the last, and every letter between gets one flat step on the way. They set --hop-start and --hop-end on the element.

Any CSS color works, var(--brand) and light-dark() included. A var() that points nowhere counts as left out, so Hue Hop picks its partner. A typo ( start="tael" ) shows plain text. Set neither end and the text keeps its normal color.

One End

Set only one and Hue Hop picks the other. It keeps your lightness and intensity and turns the hue 50 degrees around the color wheel, away from yellow. Yellow can't stay bright at a readable lightness.

As Custom Properties

Set --hop-start and --hop-end anywhere they'll inherit: :root , a class, your design tokens, or one element's style . Use them for colors shared across a site, or colors that follow a theme.

Each new attribute value adds a small style rule to the page. For a color that changes every frame, set --hop-start in style instead.

Which Value Wins

Strongest first. Each one beats everything below it.

Always wins
The style attribute, unless a stylesheet uses !important .
Beats attribute
An unlayered rule more specific than hue-hop[start] , like .card h2 hue-hop .
The attribute
start or end on the element.
Below that
A plain class rule, then any rule in a cascade layer.
The hue
The hue attribute's own colors.
Weakest
A value inherited from a parent, like :root .

From JavaScript

el.start and el.end read and set the attributes. Setting one to null removes it. Setting a property works the same as setting the attribute, even before the element has loaded. That covers frameworks that set properties (Angular, Solid, Lit's .start= ).

Keep Them Readable

The element can't see the background, so it can't check your colors for you. These rules keep both ends readable. Write your ends in oklch() so you can see the lightness (the first number).

Page Body text (4.5:1) Display (3:1)
Light, #f5f5f5 to #fff both ends at 52% or darker both ends at 62% or darker
Dark, #000 to #1a1a1a both ends at 65% or lighter both ends at 55% or lighter

These hold for any hue and any chroma a screen can show. Lightness steps evenly from one end to the other, so if both ends pass, most letters between them do too. Ends far apart on the color wheel (green to violet, say) can still dip in the middle, and lift makes that more likely. Check the middle letters.

On any other background, check the contrast yourself. The ready-made hues go a little past these numbers, because each one was measured for its own colors.

Yellows can't stay bright that dark. At 52% , a yellow holds about half the color (OKLCH chroma) a blue or pink can, so it goes dull. For a yellow start, use the display bar or a dark page.

Or let the Studio do it. It checks every letter against your page color, and its Fit button moves the ends until every letter passes, or tells you it can't.

Light and Dark

The element has no theme logic. It reads --hop-* live, so when your theme changes them, the letters follow with no re-render. Flip the side switch in the header. Examples that use a hue or light-dark() follow.

Pick colors per scheme in one of three ways. Tokens that already flip with your theme:

In your CSS

:root {
  --hop-start: var(--brand-500);
  --hop-end: var(--accent-500);
}

A scheme rule, or a class your theme switch sets (like .dark ):

In your CSS

:root {
  --hop-start: teal;
  --hop-end: royalblue;
}

@media (prefers-color-scheme: dark) {
  :root {
    --hop-start: aquamarine;
    --hop-end: lightskyblue;
  }
}

Or light-dark() , which picks its first color on a light page and its second on a dark one:

light-dark() needs color-scheme on the page ( :root { color-scheme: light dark; } ). Without it you always get the light value. This page sets it, which is why the example flips.

Drift

drift.css slowly sways the hues back and forth. Load it once (see Load It ), then add drift to the <hue-hop> .

Two custom properties set the sway. Both are plain numbers.

Property Default What it does
--hop-drift-range 24 How many degrees the hues sway each way.
--hop-drift-cycle 10 How many seconds one full sway there and back takes.

Drift only turns hues, and lightness holds. Contrast can still shift a little as the hues turn, so leave some margin at the start and end colors. Drift stops when the visitor prefers reduced motion, and under forced colors and increased contrast.

A subclass under another tag drifts too, as long as it has text. Inside another component's shadow root, load drift.css on the page and in that root.

Where It Fits

Short text that names something: a title, a name, a number. It isn't meant for body copy, which gets hard to read when every letter changes color.

Links and other inline markup can sit inside, and they keep working. The colors run straight across them. Keep link underlines on: when only part of a heading is a link, the underline is the only thing that says so (WCAG 1.4.1).

Customize

Tuning the Ramp

Three custom properties shape the steps between your two ends. None of them has an attribute. Set them once, on :root or a class, and every heading under it follows. One catch: a hue sets --hop-lift on the element itself, so to change lift under a hue, set it on the element. The examples set them in style so you can see the one value that changes.

Curve

How the steps are spaced. At 1 , the default, they're even. Higher stays near the start color longer. Lower gets to the end color sooner.

Lift

Extra color intensity (OKLCH chroma) for the middle letters, so the blend doesn't go dull halfway. The two ends don't change. The default is 0 , and every ready-made hue sets 0.021 .

Too much lift gets clipped. Past what an sRGB screen can show, the middle letters get cut back, and on a white page that can lower their contrast. Check the middle letters. The Studio checks them after the clip, so it catches this.

Shift

Turns each letter's hue by this many degrees around the color wheel. Write a plain number ( 30 , not 30deg ). The default is 0 . Lightness holds, so it's a quick way to try a pair in another color without picking new ends.

Contrast can still move a little as the hues turn. A shifted ready-made hue isn't the one that was measured, so check it.

Styling Around It

<hue-hop> is an inline element. Font, size, weight, and letter spacing work on it the way they work on a <span> . Style the heading around it as you already do.

Your color
color is the exception. The letter colors paint over it, so yours only shows where the effect is off: an older browser, neither end set, forced colors, or increased contrast. Set it anyway. It's the fallback.
Selected text
A ::selection rule of yours that sets color wins in every browser, and the letter colors come back after. Without one, Chrome and Safari keep the letter colors on the selection background. Firefox uses its own selection colors.
Gradient text
background-clip: text with a transparent fill hides the effect, because the transparent fill wins. Use one or the other.
Links inside
They lose their own color in every state, hover and visited included. They keep their focus ring and underline. Firefox and Safari keep the underline in the link's color. Chrome paints it in each letter's color, and text-decoration-color only shows under the spaces.
Your highlights
A search-term marker, say, paints above Hue Hop's, because every Hue Hop highlight has priority −1. See Highlights .

Coloring Things Nearby

Hue Hop only colors letters. To match a list marker, a badge or a border, put --hop-start and --hop-end on a shared parent and use them in your own CSS.

Using Your Own Colors

Set both ends on the parent. No JavaScript, and it follows theme switches.

--step is each item's place on the ramp: 0 is the start color, 1 the end. A border or badge can skip the mix and use var(--hop-end) .

Keep the media query
Without it, markers stay colored under increased contrast while the letters go plain.
Set both ends
The letters pick a partner for a missing end. The mix can't, so markers stay plain.
With drift
Only the letters move. Markers hold still.

Using a hue Instead

Drop the .playlist rule and run this script. A hue sets its ends on the element itself, so nothing beside it can see them. The script copies them to the parent, and they still follow theme switches.

In your JavaScript

customElements.whenDefined('hue-hop').then(() => {
  const parent = document.querySelector('.playlist');
  const styles = getComputedStyle(parent.querySelector('hue-hop'));
  for (const name of ['--hop-start', '--hop-end']) {
    parent.style.setProperty(name, styles.getPropertyValue(name));
  }
});

Middle markers look slightly less vivid than the letters, because the mix leaves out --hop-lift .

Integrate

Frameworks and Editors

It's a plain custom element. Plain HTML, Svelte, and Lit need nothing. TypeScript and React get their types from the package. Vue and Angular each need one setting.

TypeScript

hue-hop.d.ts ships in the package. It adds <hue-hop> to HTMLElementTagNameMap , so document.querySelector('hue-hop') comes back as a HueHop . It also types the element in React JSX: hue (the seven names), start , end , drift , and display . Nothing to declare.

React

React needs nothing. It sets start and end as attributes or as properties, and the element reads both.

Server rendering logs one warning in development. If the element defines itself before React 18 hydrates, the development build logs Extra attributes from the server: hops . Colors stay correct. If your test runner fails on console errors, let that one line through.

Vue and Angular

Both need to be told that <hue-hop> isn't one of their own components. In Vue, add this to the Vue plugin in vite.config.js :

In vite.config.js

vue({
  template: { compilerOptions: { isCustomElement: tag => tag === 'hue-hop' } },
})

In Angular, add CUSTOM_ELEMENTS_SCHEMA to the component that uses it:

In your Angular component

@Component({
  schemas: [CUSTOM_ELEMENTS_SCHEMA],
})

Another Tag

The HueHop class is exported. To use another tag, register a subclass:

In your JavaScript

import { HueHop } from 'hue-hop';

customElements.define('my-hop', class extends HueHop {});

HueHop itself won't work here. The import already registered it, and a class can only be registered once. Use one tag per page or shadow root. Two tags in one root make one of them fall back to plain text.

A subclass that defines its own observedAttributes must include ...super.observedAttributes and call super.attributeChangedCallback() , or start and end stop updating.

The hues and drift follow your tag on their own.

The element attaches a shadow root holding one <slot> , and your text stays where you wrote it. A subclass can attach its own root in its constructor instead. Any later and the browser throws. Keep a <slot> in it, or the text won't show. A closed root goes without the hues, because the element can't reach it.

Tailwind and Cascade Layers

CSS on the element beats a hue with no setup, layer or not. So do --hop-drift-range and --hop-drift-cycle . The one exception is a layered rule that sets animation on a drifting element. drift.css sits in a layer named hue-hop , so list that first for your rule to win.

In your CSS

@layer hue-hop, theme, base, components, utilities;

Content Security Policy

The element adds its styles from JavaScript as constructed stylesheets (built in script, not written into the page), not a <style> tag. So your policy doesn't need style-src 'unsafe-inline' for it. drift.css is a plain stylesheet file, so load it from a host your policy already allows.

Editors

custom-elements.json describes every attribute, property, and custom property in the Custom Elements Manifest format. The package's customElements field points to it, so any tool that reads the format can find it.

Testing Your App

Screenshot Tests

Drift keeps moving, so screenshots of it won't match from run to run. Emulate reduced motion and drift holds still. In Playwright:

In your Playwright test

await page.emulateMedia({ reducedMotion: 'reduce' });

Reading a Letter's Color

Each step has its own highlight: hue-hop-0 for the first, hue-hop-1 for the next, and on up. Up to 64 letters, that's one per letter. Read one with getComputedStyle :

In your JavaScript

getComputedStyle(el, '::highlight(hue-hop-0)').color;

The value is fixed for the current scheme. A copy of it won't follow a theme switch. For colors that do, see Coloring Things Nearby . Stay below el.hops : a higher step can return a wrong color.

Test DOMs

jsdom and happy-dom have no highlights, so the element goes inert there. It's defined, it never draws, and it logs nothing. That's what Vitest's jsdom and happy-dom environments do, checked with jsdom 30.1, happy-dom 21.0, and Vitest 5.1.

Wiring up a DOM by hand? The element reads CSS as it loads. Copy only window , document , HTMLElement , and customElements onto the global and the import throws ReferenceError: CSS is not defined . Copy window.CSS too and it loads in both. On jsdom, this line before the import works too:

Before the import

globalThis.CSS ??= {};

el.hops is 0 off the page or without support, test DOMs included. The hops attribute keeps its last value.

Before It Loads

Without JavaScript, or before the element loads, the heading is plain text in its normal color. When the colors arrive, nothing moves, so there's no layout shift to prevent and nothing to load ahead of it.

Older browsers show the plain heading too. The element never paints a wrong color. See Browser Support .

Highlights

The colors are highlights in CSS.highlights , one per step: hue-hop-0 up to hue-hop-63 . Every one has priority −1, so your own highlights (a search-term marker, say) paint above them. The names are public and won't change.

CSS.highlights.clear() removes the colors until the text changes or the element reconnects. To read a letter's color, see Reading a Letter's Color .

The hops Attribute

The element writes its step count on itself, like hops="13" and reads it from its own stylesheet. Don't set it. A hand-set value can miscolor the letters until the text changes.

Each letter gets its own step, up to 64. Spaces don't count. Longer text shares steps, so a 200-letter heading still runs the whole ramp with about three letters per color. Past 64, every extra step would slow each restyle on the page, theme switches and drift included.

Type in the box to watch the count.

The code leaves hops out, like every example here, because you never write it.

el.hops returns the same count as a read-only number. It's 0 when the element is off the page (the attribute keeps its last value) or the browser lacks support. With server rendering, React can warn about the attribute. See React .

Exports

The module exports the HueHop class and defines <hue-hop> with it, unless something on the page already did. To register it under another name, see Another Tag .

Browser Support

The colors need two things from a browser: the CSS Custom Highlight API, and custom properties that work inside a highlight. These versions and anything newer have both:

  • Chrome 134+
  • Firefox 140+
  • Safari 18+
Older browsers show the heading in its normal color. The element checks for CSS.highlights as it loads and does nothing without it. There's no polyfill. Chrome 105 to 133 have the API but can't read custom properties inside a highlight, so they show plain text too, never a wrong color. Safari 17 is unmeasured.

How It Works

Hue Hop never splits your text. A word stays one element in one text node, and the colors are painted over it. Here's one word taken apart. Move the fader to change how its colors are spaced.

Ranges
The CSS Custom Highlight API paints the colors. Each letter gets a StaticRange over the real text node, and each step is one highlight. So there are no spans. The element adds two things: its hops attribute, and a shadow root holding one <slot> . Your text stays where you wrote it.
Colors
Each step's color is worked out in CSS: color-mix() in OKLCH between the two ends, spaced by the curve, lifted in the middle, then turned by the shift and the drift. So a theme switch or a --hop-* change recolors the letters with no JavaScript. Read the formula in the repo.
Stylesheets
The styles arrive as constructed stylesheets. The hues sit in the element's own shadow root, as :host rules, which is why CSS on the element beats them and an inherited value doesn't. The rest goes on the document, or on the shadow root the element sits in. Each distinct start or end value becomes one rule in a sheet for that root. At 256 rules, that sheet is rebuilt from the elements still on the page.
64 steps
In Chromium and Safari each restyle costs about the square of the step count, so longer text shares steps.

Known Limits

Colors

  • The element can't check contrast at the start and end colors, so that part is up to you.
  • A typo in a color ( start="tael" ) shows plain text. A var() that points nowhere counts as left out, so Hue Hop picks its partner instead.
  • Ends far apart on the color wheel, and lift, can push the middle letters past what an sRGB screen can show. They get clipped, by an amount that depends on the colors, and on a white page that can lower their contrast. Check the middle letters.
  • User stylesheets and extensions that force a text color still show the colors. A highlight's color paints above the element's color, !important included.

Text

  • Links inside keep their focus ring and underline. They lose their own color in every state, hover and visited included.
  • Firefox and Safari keep a link's underline in the link's color. Chrome paints it in each letter's color, and text-decoration-color only shows under the spaces.
  • Selected text: a ::selection rule of yours that sets color wins in every browser. Without one, Chrome and Safari keep the letter colors on the selection background, and Firefox uses its own selection colors.
  • Find in page still shows its matches. The colors come back after.
  • Color emoji keep their own colors and use one hop each.
  • Chrome and Firefox split a ligature's colors at the step boundary. Safari paints the whole ligature in its first letter's color.
  • A letter split across two elements (a base letter in one, a combining mark in the next) counts as two hops.
  • The steps follow reading order, so mixed-direction text jumps around visually.
  • Text passed through your own <slot> inside the element isn't colored.
  • Safari can leave letters plain if they're hidden inside the hop and shown later, or if content-visibility is on the hop itself. Hide the hop with display: none or hide an ancestor. Those recolor when they show.
  • Screen-reader-only text inside the element still uses up hops, so the visible letters may not reach --hop-end .
  • Gradient-text headings ( background-clip: text with a transparent fill) hide the effect. The transparent fill wins.

Setup

  • One tag per page or shadow root. Two tags in one root make one of them fall back to plain text.
  • A subclass with a closed shadow root doesn't get the hues. Its letters still step if you set your own ends.
  • A subclass that defines its own observedAttributes must include ...super.observedAttributes and call super.attributeChangedCallback() , or start and end stop updating.
  • A subclass with no text, like one wrapping only an SVG, doesn't drift.

Troubleshooting

Nothing is colored.
  • An older browser. Below the floor the heading stays plain on purpose. See Browser Support .
  • A typo in a color ( start="tael" ). Correcting the spelling fixes it.
  • Both ends point at a var() that doesn't exist. One missing end is fine, because Hue Hop picks a partner. With both missing there's nothing to step. Define the variable.
  • Forced colors or increased contrast is on. The effect turns off on purpose. See Accessibility .
  • Two tags in one page or shadow root, like hue-hop and a subclass. One falls back to plain text, so stick to one tag. See Another Tag .
  • You put your own <slot> inside the element. Text passed through it isn't colored. Put the <hue-hop> around the text where it's written, not around the slot.
The dark hues don't show.
No color-scheme on the page, so light-dark() always picks the light side. Add :root { color-scheme: light dark; } . See Light and Dark .
My CSS doesn't override the hue.
You set --hop-* on a parent, like :root . The hue's own value on the element beats an inherited one. Set yours on the element. See Change One End .
The middle letters look wrong.
Ends far apart on the color wheel, or too much lift, push the middle letters past what an sRGB screen can show, and they get clipped. Lower the lift or bring the ends closer, then check the middle letters. See Lift .
React warns about hops .
Server rendering. The server's HTML has no hops , and the element writes it before React 18 hydrates, so the development build prints Warning: Extra attributes from the server: hops . It's harmless, and the colors stay correct. If your test runner fails on console errors, let that one line through. See React .
Drift doesn't move.
  • drift.css isn't loaded. Load it (see Load It ).
  • The element is in another component's shadow root. Load drift.css on the page and in that root.
  • Reduced motion is on. Drift holds still on purpose, and under forced colors and increased contrast too.
Colors don't follow my theme switch.
--hop-* set on :root in a prefers-color-scheme query, while your theme switches on a class. Set them under that class too.

Still stuck? Ask in Issues (see Support ).

Inspiration

It started with the per-letter wordmark on mdrng.com , and one idea:

Each letter's color should be chosen, not smeared.

Why stepped
One flat color per letter is a choice you can check. Every letter's contrast is a number.
Why now
The CSS Custom Highlight API ships in Chrome, Firefox, and Safari. That's what lets the text stay text.
